# 多任务鳄鱼布局

设计、代码、自动化与真机验收已完成（2026-11-19）。本文详细说明功能总规格中的多任务改版，实施证据统一回填功能总规格。

## Problem Statement

当前两个及以上任务会隐藏鳄鱼，使用全宽任务列表。短标题和固定行距又留下大片空白。用户看不到宠物，也不能快速识别哪些任务需要自己回答或批准。

## Solution

采用方案 A，在 400×300 屏幕上同时显示任务概览和 90×120 鳄鱼，每页最多 3 个任务。文字上方使用整行宽度，下方避开鳄鱼。等待回答或审批的任务置顶并反白显示状态；新等待优先且返回首页，鳄鱼和待处理总数反映全部页面。

## User Stories

1. 作为设备用户，我希望两个任务时也显示鳄鱼，以保持陪伴感。
2. 作为设备用户，我希望三个及以上任务时仍显示鳄鱼，以获得一致的体验。
3. 作为设备用户，我希望鳄鱼保持 90×120，以看清动作细节。
4. 作为设备用户，我希望每页最多显示 3 个任务，以快速了解工作概况。
5. 作为设备用户，我希望上方标题用足屏幕宽度，以减少截断。
6. 作为设备用户，我希望下方文字避开鳄鱼，以清楚识别文字和形象。
7. 作为设备用户，我希望每项显示标题和状态，以分辨各项工作。
8. 作为设备用户，我希望长标题带省略号，以识别未显示完整的内容。
9. 作为设备用户，我希望中英文和长路径都不越界，以避免文字丢失。
10. 作为设备用户，我希望等待回答的任务优先显示，以及时作答。
11. 作为设备用户，我希望等待批准的任务优先显示，以及时处理审批。
12. 作为设备用户，我希望等待状态黑底白字，以一眼识别待处理事项。
13. 作为设备用户，我希望标题保持白底黑字，以便阅读。
14. 作为设备用户，我希望新等待排最前，以看到最新事项。
15. 作为设备用户，我希望普通更新不改变等待顺序，以避免任务换位。
16. 作为设备用户，我希望新等待出现时回首页，以免漏掉事项。
17. 作为设备用户，我希望仍可手动翻页，以查看其他任务。
18. 作为设备用户，我希望普通更新保留手动页，以免阅读被打断。
19. 作为设备用户，我希望页头显示全局待处理总数，以知道其他页仍有等待。
20. 作为设备用户，我希望任一页有等待时鳄鱼都显示等待动作，以持续提醒自己。
21. 作为设备用户，我希望全部任务恢复工作后显示工作动作，以知道无需干预。
22. 作为设备用户，我希望等待解除后撤销高亮，以免提醒已处理事项。
23. 作为设备用户，我希望单任务、完成停留和底栏保持现有行为，以继续使用熟悉的界面。
24. 作为设备用户，我希望相同画面不反复刷新，以减少墨水屏闪烁。

## Implementation Decisions

1. 鳄鱼保持现有素材、尺寸和右下位置。文字在鳄鱼区域左侧收窄，上方使用整行宽度。
2. 每个任务显示标题与状态。长标题按实际可用像素宽度截断，并显示省略号。
3. 等待回答、等待批准操作的任务排在工作任务之前。等待状态用黑底白字状态条；标题保持白底黑字。
4. 新进入等待的任务排在最前。已有等待任务保持相对顺序，普通进度和心跳更新不改变顺序。
5. 新等待出现时自动回到第一页。用户可手动翻页；普通进度更新保留当前页。
6. 鳄鱼反映全部任务。任一页面存在等待任务时显示等待动作；全部活跃任务都在工作时显示工作动作。
7. 多页时显示页码。页头显示待处理事项总数，让用户在后面的页面也能识别尚有等待。
8. 报错、已停止、状态陈旧及单任务的既有显示规则继续适用。
9. 复用任务模型、显示顺序、翻页、布局与光栅化模块，不另建渲染链路，不做预先的大范围重构。继续遵守单主角六动作、素材契约与刷新合并决策。
10. 最后一页只有一项时仍使用多任务布局，不切换成单任务详情。页头待处理总数按等待任务计数，同一任务存在多项等待仍计为一项待处理任务。
11. 等待状态分别显示“等你回答”和“等你批准”。类别来自真实等待事件信息，不依赖显示文案猜测；不扩大问题正文的读取和显示范围。
12. 退出等待后再次进入才算新等待。重复扫描、等待期间的心跳和进度更新不算新等待。同批新等待采用稳定次序；启动恢复不产生反复跳页。
13. 普通更新和自动聚焦不得覆盖手动页。任务消失或页数减少后保持页码有效。
14. 等待顺序所需信息集中在任务模型中维护，扫描和布局复用同一来源。旧状态缓存保持可读，不新增标题或问题正文副本。

## Testing Decisions

- 复用现有“任务事件进入模型 → 翻页 → 布局输出 → 400×300 预览”入口，以用户可见行为为断言，不测试私有字段的组织方式，不新增测试框架。
- 测试任务模型和布局模块，沿用固定行、等待置顶、页码、素材边界和单帧元素上限的既有测试。

- 2、3、4 个任务与多页最后一页均显示鳄鱼；文字、状态条与鳄鱼互不重叠。
- 标题按像素宽度处理，中英文和长路径均保持在可用区域内。
- 多个等待优先于工作任务，新等待置顶，重复扫描与心跳保持既有顺序。
- 新等待使后续页回到第一页；处理后撤销高亮；普通更新保留手动页。
- 翻到只有工作任务的页面，其他页面尚有等待时，鳄鱼仍显示等待动作，页头保留待处理总数。
- 所有任务恢复工作后，鳄鱼显示工作动作。
- 原有单任务、完成停留、底栏和刷新节流的检查通过；单帧元素数符合既有上限。
- 同批新等待、重复扫描、恢复旧缓存与任务消失均有事件序列覆盖；自动聚焦不得撤销手动翻页。
- 正式渲染器生成预览；每票运行相关测试，最终运行现有 Rust 和插件测试及构建检查。真机验收由用户完成，预览通过不记作真机通过。

## Out of Scope

- 新素材、缩小鳄鱼、动画、装扮、完整标题详情页与重点任务方案。
- 报错、停止和陈旧任务的新提醒队列。
- 提示音策略、设置页、配置桥、花絮内容和编辑入口变更。
- CI、SDK 版本固定、二进制哈希等供应链工作。
- 本次实现不包含安装、发布、远端推送或 DSH 重启。

- 用户已确认方案 A 细化预览及本规格的交互规则，包括页头待处理总数。
