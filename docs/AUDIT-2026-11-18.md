# 代码审计与整改票（2026-11-18）

对象：`E:\myAIProjects\zetrix-dsh-screen`，Cargo 0.7.4，`cargo test --offline` 54 lib + 15 bin 全绿。

## 一句话结论

工程卫生整体不错（无密钥入库、无 shell 拼接、state.json 原子写），但有三件必须修的事：**配置桥无鉴权**、**隐私承诺与实现不符**、**state.json 解析失败会被默认值覆盖**；另有约 1/3 死代码、若干可用性与性能问题。

## P0（必须修）

### T1 配置桥鉴权与最小暴露

- 问题：`plugin/index.js` 的 127.0.0.1:4517 无 token，且所有响应带 `Access-Control-Allow-Origin: *`。任意网页可读 `target`、读本机安装路径、改 `target`（标题就会被发到攻击者主机）、用 `/test` 扫局域网。
- 修法：每安装随机 token（落 `%LOCALAPPDATA%\zectrix-dsh-pet\bridge-token`）；`/token` 只在 Origin/Sec-Fetch-Site 合法时返回；其余接口校验 token；ACAO 只回白名单；`/health` 不含路径；`/test` 只测已存 target；target 限定 IPv4 字面量；body 限长并校验 content-type。
- 验收：无 token → 401；伪造 Origin/跨站 → 403；正常客户端 200；`node:test` 覆盖上述四种情况。

### T2 隐私契约对齐（标题 / 提问 / 日志）

- 问题：README/dsh.rs 声称不读对话正文，实际 `user_title()` 取用户消息首行当标题，`ask_text()` 取提问正文当 detail；state.json（74 条）、pet.log、设备屏幕全都有正文痕迹。
- 修法：默认只用 DSH 会话标题，没标题用「项目名 + 第 N 轮」；新增 `title_source=session|prompt`（默认 session，prompt 需显式开启并标注风险）；等待状态只显示「有 1 个问题待确认」；announced 只存 hash；pet.log 不记标题；提供 `dsh-pet forget --titles` 清历史。
- 验收：默认配置下新写入的 state.json / pet.log 无正文；4 个单测；文档与实现一致。
- 决策：已确认允许一次性清掉历史旧标题。

### T3 state.json / pet-config 损坏保护与原子写

- 问题：解析失败返回默认 Store，下一次保存会把 42KB 历史整份覆盖，且无备份；pet-config 一个字段类型错整份被忽略。
- 修法：解析失败先把原文件改名 `.corrupt-<ts>.json` 并进入 degraded（拒绝覆盖，只写 recovered）；每次成功保存保留 `state.bak.json`；pet-config 逐字段容错 + tmp/rename 原子写；插件端写配置也改原子写。
- 验收：坏 JSON 演练生成 `.corrupt-*` 且原文件不被清空；4 个单测。

## P1（应该修）

### T4 autostart 与快捷方式生命周期

- 问题：`autostart on` 写的 VBS 指向已不存在的 `panel --tray`；`cmd_watch` 每次启动又把该 VBS 和快捷方式删掉，自相矛盾。
- 修法：删除自启写入与快捷方式创建；只保留一次性、幂等的旧文件清理；install.ps1 与文档同步。
- 验收：不再写任何启动项；旧残留被清；无 `panel --tray` / `schtasks` 残留。

### T5 配置双份收敛为单源

- 问题：`pet-config.json` 与 `state.json` 都能存设置，`settings_explicit=true` 让合并分支失效；CLI 改的值会被一次插件保存回滚；并发保存丢字段。
- 修法：定契约 `pet-config.json` = 唯一用户配置源，state.json 只存运行时快照；删除 explicit 标志；CLI `set` 写 pet-config；统一配置应用入口；保存加锁。
- 验收：CLI 与插件交替保存不互相回滚；4 个单测；文档配置表同步。

### T6 设备可用性

- 问题：断线后可能 4–5 分钟不更新；录音事件无超时（卡死在录音图标）；UIA 花絮在推送路径上阻塞 1.5 秒；双击手势一次闪 3 屏。
- 修法：断线原地重连 3 次（1/2/4s）再退避；录音 10 秒超时复位；UIA 花絮后台 2 秒采样；单击立即推、双击只在判定窗结束后推一帧。
- 验收：拔网 30 秒内恢复；录音超时复位；推送路径无 UIA 阻塞；双击最多 2 帧。

## P2（可以改）

### T7 死代码清理（净减 ≥1200 行）

- 删除：voice 模块 1108 行及 CLI（决定：删除）、skin 六套造型全链路、animation 假开关、balance 命令、data_dir 迁移死分支、重复 retain 条件、两处死分支、空 locales、孤儿 `.pyc`。
- 验收：0 warning（无 dead_code allow）、69+ tests 绿、README/USAGE/SPEC 同步。

### T8 主循环性能与节流

- 问题：1 秒 tick 上跑 tasklist、24 份日志 open/read、3 次 state.json 解析、`to_string` 签名、UIA 阻塞、频繁 fsync。
- 修法：state.json 按 mtime 缓存、签名改 hash、UIA 移出推送路径、tasklist 降到 5 秒、save 节流、TeamScan 定期 prune。
- 验收：空闲 60 秒 CPU <0.5%、每拍 0 次 state.json 解析、无回归。

### T9 main.rs 拆分与测试补齐

- 现状：main.rs 3491 行，配置/扫描/守护/CLI/Windows 外壳混在一起；桥与配置合并无测试。
- 修法：拆成 store / config / scan / daemon / cli 五个模块（先移动不改行为）；补 ≥12 个 Rust 测试 + JS 桥测试；测试总数 ≥80。
- 验收：main.rs <800 行；干净 clone 可跑单测；三条链路（推送/设置/启停）手测通过。
